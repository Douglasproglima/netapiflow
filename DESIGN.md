## Text on tinted background (on-tint)

A semantic color used as text directly on its own tinted background (banner, chip, tag) is a
different contrast pair than the same color on a flat surface. Verified 2026-11-04 against the
specific tinted backgrounds already in use:

| Token | Theme | Hex | Verified against | Ratio |
|---|---|---|---|---|
| `--naf-danger-on-tint` | Obsidian | `#F87171` | `#2D1C26` (error-origin banner) | 5.81:1 |
| `--naf-danger-on-tint` | Obsidian | `#F87171` | `#2B1A22` (DELETE tag) | 5.96:1 |
| `--naf-warning-on-tint` | Stage Light | `#92400E` | `#EBE5E1` (slow chip) | 5.68:1 |
| `--naf-warning-on-tint` | Stage Light | `#92400E` | `#EFE8E3` (PUT tag) | 5.85:1 |
| `--naf-success-on-tint` | Stage Light | `#065F46` | `#D9E9E9` (POST tag) | 6.14:1 |
| `--naf-success-on-tint` | Stage Light | `#065F46` | `#DDEBEB` (POST tag, variant) | 6.28:1 |

Any pair not listed here falls back to the base color (`--naf-danger-on-tint: var(--naf-danger)`,
etc.): no failure was measured for that theme/color combination yet. Use the `-on-tint` token,
never the base color, whenever semantic text sits on its own tinted background.

## Typography

Dense type scale for a dashboard, applied consistently across every screen
(`docs/design/flow-workspace/guide.md`, section 3.3). The implementation must match this table
exactly: a role rendered at any other size is a defect, not a design choice to re-litigate.

| Role | Family | Size / line-height | Weight |
|---|---|---|---|
| Page title (topbar) | Plus Jakarta Sans | 18 / 24 | 700 |
| Metric value | Plus Jakarta Sans | 24 / 28, tabular nums | 700 |
| Card title | Inter | 14 / 20 | 600 |
| Body, list items | Inter | 13 / 20 | 400 and 500 |
| Label, caption | Inter | 12 / 16 | 500 |
| Small metric, duration, route, trace id, verb | JetBrains Mono | 12 / 16, tabular nums | 400 and 500 |
| HTTP verb badge | JetBrains Mono | 11 / 16, letter-spacing .04em | 600 |

Nothing in the dashboard renders below 11px. The node label inside the graph stays at 12px
minimum **at 100% zoom**.

Families: Plus Jakarta Sans (display, page title, metric value), Inter (interface, body, card
title), JetBrains Mono (metrics, code, HTTP).

## Node visual state

Color, icon, and text together, never color alone (brand rule, reinforced by the project's own
accessibility stance, not just a tracing requirement). Icons in `docs/brand/node-states/`, 16×16,
mapping `NodeVisualState`: waiting, running, completed, slow, error, not-executed (dashed stroke).

## Deliberate exceptions to automated design checks (ADR-0014)

- **Violet/purple as the primary color**: flagged by some AI-slop detectors as the default palette
  of AI-generated interfaces. Here it's the brand identity (ADR-0009), not an unexamined default.
  The real visual distinction comes from the technical flow icons (HUD-style corner marks) and the
  node-state icons, not from color alone.
- **Inter at ~92% of interface text**: the interface font defined by the brand guide, not an
  unexamined default either.

Replacing the primary color or the interface font requires a new ADR that explicitly supersedes
ADR-0009, not a silent change to quiet a detector.
